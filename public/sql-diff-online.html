How the SQL Diff Tool Works

Using the SQL diff tool is straightforward: paste your original SQL query in the left panel and the modified version in the right panel, then click Compare. The tool tokenizes both queries into their component parts—keywords, identifiers, string literals, numbers, and operators—and uses a longest-common-subsequence algorithm to identify matching segments.

Lines that exist only in the original appear in red (removed). Lines that exist only in the modified version appear in green (added). Lines that appear in both but have differences are shown in yellow with the specific changed tokens highlighted inline, so you can see exactly which field name was renamed or which value was updated.

Frequently Asked Questions

How do I compare two SQL queries online?

Paste the original query in the left panel and the modified query in the right panel, then click Compare. The tool tokenizes both queries and uses a longest-common-subsequence algorithm to show what was added (green), removed (red), and changed (yellow) - down to the individual field name or value.

Can this tool compare MySQL and PostgreSQL DDL?

Yes. The diff understands dialect-specific syntax such as MySQL backticks and AUTO_INCREMENT, PostgreSQL SERIAL types, :: casting, and dollar-quoted bodies. You can even compare a MySQL statement against its PostgreSQL rewrite to see exactly what the migration changed.

Is my SQL data safe when using the diff tool?

Yes. Every comparison runs client-side in your browser - nothing is uploaded and no query text is stored or logged. You can verify it by disconnecting from the network after the page loads: the diff still works.

How is this different from a text diff tool?

A text diff compares lines character by character, so a reformatted query looks completely different even when the logic is identical. This tool tokenizes SQL first, so it distinguishes a renamed column from a re-indented clause and highlights the precise token that changed.

Can I compare stored procedures or migration scripts?

Yes. Stored procedure bodies, view definitions, and migration scripts all diff the same way - paste the before and after versions. For very long scripts, compare one statement at a time so the highlighted changes stay easy to review.

Is there a size limit for the SQL I compare?

No server-side limit, because the comparison runs in your browser. Practical limits come from your machine's memory: queries and scripts of a few megabytes diff instantly, and multi-megabyte dumps are better compared statement by statement.

Does the diff ignore whitespace and formatting differences?

It tokenizes SQL before comparing, so pure re-indentation and line-break changes do not drown the real differences. Actual content changes - a renamed column, a changed literal, a new WHERE condition - are always highlighted.
