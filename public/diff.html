What is a SQL Compare Tool?

A SQL compare (or SQL diff) tool highlights the differences between two SQL scripts so you can see exactly what changed without squinting between two windows. Paste an original query and a modified version, and the tool lines them up using a longest-common-subsequence algorithm, marking added lines in green, removed lines in red, and modified lines in orange. On modified lines it goes a step further and highlights the individual tokens that changed, so a one-column rename or a changed join condition is obvious at a glance. It is the fastest way to review query edits, track schema changes, or understand what a colleague changed in a shared script. Unlike a plain text diff, a SQL-aware compare keeps the result readable by tokenizing keywords, strings, and identifiers, so the highlighted changes map directly to query semantics rather than raw characters. Because the comparison runs on SQL tokens rather than raw lines, it tolerates harmless reformatting while still surfacing real logic changes.

How to Use the Compare Tool

  1. Paste the original SQL into the left panel (A) and the modified SQL into the right panel (B).
  2. Click Compare, or press Ctrl+Enter in either panel.
  3. Read the diff — green + marks added lines, red − marks removed lines, and orange ~ marks modified lines.
  4. On modified lines, inspect the inline highlighting to see the exact tokens that changed.
  5. Use the stats bar (added / removed / modified / unchanged) to gauge how large the change is, or click Example to load a sample schema diff.

Common Use Cases

  • Reviewing pull requests that modify SQL migrations or stored procedures.
  • Comparing a query before and after an optimization to confirm only the intended parts changed.
  • Auditing schema differences between two versions of a database.
  • Verifying that a formatter or linter only reformatted code without changing logic.
  • Tracking edits made by teammates to shared reporting queries.
  • Comparing database schema exports across environments (dev, staging, production).

Example

Compare two versions of a query — the tool marks the join change, the filter change, and the new column.

-- Original (A): SELECT u.name, u.email, o.amount FROM users u JOIN orders o ON u.id = o.user_id WHERE o.status = 'pending'; -- Modified (B): SELECT u.name, u.email, u.phone, o.amount FROM users u LEFT JOIN orders o ON u.id = o.user_id WHERE o.status = 'completed'; -- Detected: 'JOIN' -> 'LEFT JOIN' (modified), -- 'pending' -> 'completed' (modified), -- 'u.phone' (added)

Tips

The comparison is case-insensitive on trimmed line text, so formatting-only differences (extra spaces, line breaks) are surfaced as “modified” at the token level — perfect for verifying that a formatter didn't change logic. For large scripts, glance at the stats bar first, then scroll to the orange modified lines where the real logic lives. If two queries look wildly different because of reordering, run both through the SQL Formatter first so the diff aligns on structure rather than whitespace. All processing happens in your browser, so you can safely compare sensitive or proprietary SQL without uploading it anywhere. If the two inputs are very long, paste only the changed region to keep the diff output fast and easy to scan.
